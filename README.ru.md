# workspace-server

Тонкий локальный хаб. Он хранит версионированные JSON-документы в папке на этой машине и отдаёт их тем приложениям в локальной сети, которые о них попросят. Здесь нет ни базы данных, ни схемы, ни понимания того, что означает тот или иной документ: приложение сохраняет что хочет и само же сливает версии.

Он нужен для того, чтобы данные приложения переживали то, что браузер не гарантирует: очистку данных сайта, вытеснение хранилища и удаление Safari всего подряд после семи дней без визитов.

## Чем он не является

Он не источник истины. Приложения, которые им пользуются, держат собственную локальную копию и относятся к серверу как к ещё одному участнику сети — тому, у кого есть диск и нет собственного сборщика мусора. Благодаря этому приложение продолжает работать, когда эта машина выключена или телефон унесли из дома.

Он также не выполняет слияние. Если два устройства пишут один и тот же документ, они разбираются между собой сами, пользуясь etag, который выдаёт этот сервер. См. раздел «Конкурентная запись» ниже.

## Запуск

```
DATA_ROOT=./data \
TLS_CERT=./certs/server-cert.pem \
TLS_KEY=./certs/server-key.pem \
ALLOWED_ORIGINS=https://you.github.io/app \
npm start
```

При старте он печатает URL, токен и код сопряжения, который нужно вставить или отсканировать в приложении.

| Переменная        | Значение                                                                          |
| ----------------- | --------------------------------------------------------------------------------- |
| `DATA_ROOT`       | Обязательна. Папка, в которой хранятся документы.                                 |
| `PORT`            | По умолчанию `8443`.                                                              |
| `TLS_CERT`        | Сертификат. На практике обязателен — см. ниже.                                    |
| `TLS_KEY`         | Парный закрытый ключ. Либо оба параметра, либо ни одного.                         |
| `ALLOWED_ORIGINS` | Список через запятую. `localhost:5173` и `:4173` разрешены всегда.                |
| `TOKEN`           | Переопределяет сохранённый токен. Иначе один раз генерируется в файл `.token`.    |
| `PUBLIC_HOST`     | Имя хоста, которое сервер сообщает о себе. По умолчанию `<hostname>.local`.       |

## HTTPS не опционален

Страница, отданная по HTTPS, не может обратиться к обычному HTTP-адресу в локальной сети. Chrome и Edge смягчают это ограничение, только когда выдано разрешение на доступ к локальной сети, а **Safari отказывает наотрез — он блокирует смешанное содержимое даже для `http://localhost`**. Поскольку установленное PWA отдаётся по HTTPS, сервер без TLS доступен только с собственной машины.

Сертификаты выпускает [mkcert](https://github.com/FiloSottile/mkcert):

```
mkcert -install
mkcert -cert-file certs/server-cert.pem -key-file certs/server-key.pem \
       "$(hostname).local" 192.168.x.x localhost 127.0.0.1
```

На каждом устройстве, которое обращается к серверу, должен быть установлен корневой сертификат mkcert. На iOS это два шага, и второй легко пропустить: установите профиль, **затем** откройте Настройки → Основные → Об этом устройстве → Доверие сертификатов и включите полное доверие. Без второго шага iOS по-прежнему отвергает сертификат.

Закрепите за машиной адрес через резервирование в DHCP. В сертификате указан IP, а сертификат с прошлонедельным IP — это сертификат ни для чего.

## Разрешение на доступ к локальной сети

Chrome и Edge не дают публичной странице обращаться к приватному адресу, пока пользователь этого не разрешит, и никакой заголовок ответа не может выдать это разрешение от имени страницы: `Access-Control-Allow-Private-Network` отправляется, но сам по себе его недостаточно. Первая синхронизация с конкретного сайта вызывает запрос разрешения; разрешите его один раз на каждом устройстве. По измерениям на этой машине, заблокированный запрос падает примерно за 5 мс с голым `TypeError`, неотличимым от выключенного сервера.

## API

```
GET  /api/health                    -> 200 {name, version}          токен не нужен
GET  /api/apps/:app/docs/:doc       -> 200 <body> + ETag, или 404
PUT  /api/apps/:app/docs/:doc       -> 201 создан / 200 обновлён + ETag
```

Всё, кроме `/api/health`, требует заголовок `Authorization: Bearer <token>`.

`:app` и `:doc` должны соответствовать `^[a-z0-9-]{1,64}$`. Всё остальное — 400: эти имена становятся сегментами пути, а белый список не способен выразить «подняться на каталог выше» так, как приходится предугадывать это чёрному списку.

### Конкурентная запись

Каждый `PUT` обязан нести предусловие:

- `If-None-Match: *` — создание; 412, если документ уже существует.
- `If-Match: "<etag>"` — обновление; 412, если документ изменился с тех пор, как вы его прочитали.

Безусловной записи нет. Каждый клиент либо прочитал etag, либо получил 404, поэтому каждый может сказать, в каком он случае, а случайное затирание чужих данных становится невозможно выразить, а не просто нежелательно.

При 412 клиент перечитывает документ, снова сливает изменения и повторяет попытку. Etag — это SHA-256 хранимых байтов, поэтому одинаковое содержимое всегда даёт одинаковый etag, а запись, ничего не меняющую, можно обнаружить бесплатно.

Тела хранятся ровно теми байтами, которые были присланы, и никогда не разбираются и не сериализуются заново — иначе тело, вернувшееся с другими пробелами, меняло бы etag без чьей-либо правки, и каждый клиент видел бы фантомный конфликт. На корректность JSON они по-прежнему проверяются; их просто никогда не переписывают.

Запись атомарна: временный файл в том же каталоге, сброс на диск, затем переименование поверх целевого. Читатель видит либо старый документ, либо новый, но никогда не половину того или другого.

## Структура хранилища

```
<DATA_ROOT>/
  .token
  todo/
    data.json
```

Обычные файлы, которые можно читать и править вручную, пока сервер работает: он читает при каждом запросе и ничего не кэширует.

## Тесты

```
npm test        # vitest
npm run build   # tsc --noEmit
```

HTTP-тесты работают с Fastify через `inject`, поэтому им не нужны ни порт, ни сертификат, и гонки при завершении теста исключены.
