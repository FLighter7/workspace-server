## The files plan

- **Stage 6 of the files plan** (2026-11-13; the working file `tmp/plans/2026-11-13-files-plan.md`, outside git; stages 0 to 5 are done, see [architecture.md](architecture.md)): todo moves to the client package's engine for several documents (`1.0.0-rc.2`, F10–F17), checked through `link:` until the user publishes it, with the divergence's dialog and the buttons of an interrupted transfer.
- **A divergence does not end by itself** when both servers come to hold the same set while it waits (a device that syncs with both writing the same merge to each): a device still has to choose, and nothing is then written. Comparing the two sets while waiting would need the app's session to the main kept open; left out for now.
- **No app asks yet:** the client package's engine names a divergence (`state.diverged`) and answers it (`resolveDivergence`) since stage 5, but todo shows no question until stage 6; meanwhile a diverged app waits.
- **The subordinate's devices are not told of a choice made on the main** until it reaches the subordinate: while the two are apart, they keep showing the question, and a choice they make there wins.
- **Puts on an HDD are slower than the channel:** 26–28 MiB/s against about 48 (the files plan's stage 2, `tmp/reports/files-stage2/memory.md`); what is left is the disk's own cost of the fsync of the complete body (about 2.7 s per 256 MiB on the test HDD) and of the progress records (at most every 5 s). Possible optimizations, from stage 0 (`tmp/reports/files-stage0/`): a writer goroutine with a queue for large bodies (full speed for memory), and a larger SCTP receive buffer (`SetSCTPMaxReceiveBufferSize` 4 MiB: pion/sctp 1.12.0 is slow to leave a full receive window after the message handler pauses).

- **The diagram** (`docs/images/connections*.svg`) was rendered and checked only on Windows (Chromium and WebKit, with glyphs 7% wider standing in for Mac fonts): look at it on GitHub, light and dark theme, and in Safari on the Mac.
- **Replacing a document under a reader where POSIX renames are missing:** on FAT, exFAT, an SMB share or Windows before 10 1809, `fsutil.Rename` falls back to `os.Rename` on `ERROR_INVALID_PARAMETER`, `ERROR_NOT_SUPPORTED` or `ERROR_INVALID_FUNCTION`, the errors the documentation and Go's own fallbacks lead one to expect; none was observed. Check on a FAT or exFAT volume (a VHD will do) that the fallback is taken and that a commit over an open reader then fails as "busy" rather than corrupting anything.
- **A commit cut short by a real crash or power loss:** the store's recovery (the journal applied again at the next operation or start) is tested by making each file operation fail in turn, not by killing the process or the power; nor has a long transaction resumed across a real restart of an installed server.
- **"Open folder" on the Apps tab:** `autostart.OpenFolder` called from a console process on Windows 10 (2026-11-14) opened an Explorer window at exactly that folder (checked through `Shell.Application.Windows()`). Still unchecked: from a server started at login (no console), whether it comes in front of the browser or opens behind it (a background process may not take the foreground; the guide warns that it may open behind); and in Finder on the Mac.
- **Older, unchecked:** the mDNS responder on a Windows machine with several adapters; whether a device connects right after "Allow" in the Windows Firewall dialog of a first start.

## Known gaps

- **`forget` through a subordinate does not reach the main** (L20): the main keeps the device until it is removed on the main's page. Relaying it needs a new frame.
- **The device registry travels in one frame** of at most 256 KiB: about 700 devices with a full list of 1,000 removals. A family near that size needs the registry split over several frames.
- **A server removed on one side during a split** cannot be told by the other (L29); two mains then stay mains until the user unlinks or links one by hand.
- **A promoted main dials the servers it waits for** up to every 5 minutes until each has followed it once (L30), a laptop asleep included.
- **An `apps` answer can arrive after a newer `apps` push** on a link session, so a subordinate may sync an older app list until the next change or reconnect. Rare; answering under the same lock as the pushes, as the registry does, would close it.
- **The main's page keeps showing a code an `invite` revoked** until it expires (L21); pairing with it then gets `badSecret`.
- **The Upstream server section on a promoted main is wordy;** tighten its text.
- **Older servers** (moot until releases differ, since none of these versions was released): a main from before `invite` answers it with `protocol`, which closes the link session, and the subordinate opens it again (untested); a subordinate from before the switch of the main would halt on `takeOver`.
- **todo on `1.0.0-rc.1` does not sync with a server built from `main`:** since stage 2 of the files plan (2026-11-13) the contract is the set of documents with transactions, which that package does not speak; and todo's `e2e/server-sync.spec.ts` and `e2e/server-hub.spec.ts` read `<dir>/apps/todo/…`, which a server built from `main` keeps in `<dir>/WSS-Data/apps/todo/…` (D12). They pass against `v1.0.0-rc.1`, which todo's CI checks out; run locally against `../workspace-server`, they fail until todo moves (stage 6). Since stage 5 the client package's engine has another adapter (F10) and pairing record (F16), so todo builds against `client/` only once it moves (stage 6); its devices pair again then. The installed server and todo are updated together.
- **The installed server ignores data in the old layout:** a server updated from before 2026-11-13 finds no data in `<data folder>/apps/` (nothing migrates, D12); move it into `WSS-Data/apps/` by hand, or start over.
- **The main's Apps tab drops a divergence's mark once a device of the main chose,** while the choice still waits to reach the subordinate (`Hub.Divergences` lists only those waiting for a choice); the subordinate's page keeps the mark until the choice arrives there.
- **An installed server updated past 2026-11-13** keeps an old `history/` folder in each app's folder, unused (delete it by hand), and logs `history` and `maxBytes` in `apps.json` as unknown keys, giving each app the default quota.
- **Docker:** an image for a NAS is a later step; it needs host networking for UDP and mDNS.
